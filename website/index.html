Shuttle reads your source once, writes to every destination at the same time, and verifies each copy against the original. What you get is a first copy you can trust — and a record that proves it.

For DITs, camera assistants and production teams.

01 · Architecture

Read once.
Write everywhere.

Shuttle reads each file from the source exactly once and streams it to every destination at the same time. Adding a second or third copy doesn’t mean another pass over the card — it means another drive receiving the same read. Every destination is tracked and verified on its own.

02 · Verification

Verify everything.

After the write completes, Shuttle reads every file back from each destination and compares it with the hash computed during the source read. Mismatches are reported by file and by destination. Nothing is sampled, and nothing is marked complete until it has been checked.

XXH3 by default · MD5 and SHA-256 when required

03 · Recovery

Resume without starting over.

Shuttle records durable checkpoints as it works. If a drive is unplugged, a disk fills up or the app is quit mid-transfer, nothing that was verified is lost. Reconnect, reopen, and Shuttle continues from the last good file — after confirming the source hasn’t changed underneath it.

What happens What Shuttle does

A drive is unplugged mid-transfer

That destination pauses. The others keep writing. When the drive returns, Shuttle resumes it from the last checkpoint instead of starting again.

A destination fills up

The transfer continues to the remaining destinations. The full one is reported with exactly which files are missing, so it can be finished elsewhere.

The transfer is interrupted, or the app restarts

Progress is saved continuously in durable checkpoints. Reopen Shuttle and continue where it stopped. Verified files are never copied twice.

The source changes

Before resuming, Shuttle checks that the media is the same media. If the card was modified or swapped, it says so rather than picking up against the wrong files.

Destination data is damaged later

Any past transfer can be re-verified from History. Mismatches are listed file by file, with the original hashes to compare against.

A failure on one destination never touches the others.
